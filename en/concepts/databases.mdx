Hyze Cloud provisions and operates managed databases inside your workspace. You create the instance through the API or dashboard, receive a connection string, and inject it into your app as an environment variable.

## Available engines

| Engine | Typical use |
| --- | --- |
| PostgreSQL | Relational data, the default for most APIs |
| MySQL | Relational data with a MySQL ecosystem |
| MongoDB | Document data |
| Redis | Cache, queues, and counters |

## How apps connect

On creation, Hyze returns a `connectionString`. Store it as an app environment variable:

```json
{
  "name": "prod-postgres",
  "engine": "postgresql",
  "memoryMB": 1024,
  "storageGB": 20
}
```

```bash
curl -X PUT https://api.hyzecloud.com/api/apps/app_001/env \
  -H "Authorization: Bearer hyze_your_key" \
  -H "Content-Type: application/json" \
  -d '{ "envVars": { "DATABASE_URL": "postgresql://user:pass@host:5432/db" } }'
```

<Callout type="warning">
  Treat the connection string as a secret. It grants full data access. Never commit it, never paste it into logs, and rotate the password if it leaks — `POST /api/databases/:id/rotate-password`.
</Callout>

## Operations

Hyze handles the lifecycle: start, stop, stats, logs, backups, and restore. All available through the [databases API](/api-reference/databases).

By default, creation uses `memoryMB: 512` and `storageGB: 5` (minimums of 256 MB and 1 GB).
