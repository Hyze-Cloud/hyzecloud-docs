Use app environment variables for values that change between environments or should not be committed to your code.

## Common secrets

| Secret | Typical variable | Where it comes from |
| --- | --- | --- |
| Database URL | `DATABASE_URL` | Database creation response |
| API key | `HYZE_API_KEY` | Dashboard or keys API |
| Session secret | `SESSION_SECRET` | Your app or auth provider |
| Webhook secret | `WEBHOOK_SECRET` | Third-party integration |

## Update app variables

```bash
curl -X PUT https://api.hyzecloud.com/api/apps/app_001/env \
  -H "Authorization: Bearer hyze_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "envVars": {
      "NODE_ENV": "production",
      "DATABASE_URL": "postgresql://user:pass@host:5432/db"
    }
  }'
```

<Tip>
  `PUT /api/apps/:appId/env` merges the variables you send into the existing environment.
</Tip>

<Callout type="warning">
  Variables are injected at startup. Restart the app after changing values used during boot.
</Callout>

## Rotate an API key

<Steps>
  <Step title="Create a replacement key">
    ```bash
    curl -X POST https://api.hyzecloud.com/api/api-keys/ \
      -H "Authorization: Bearer hyze_your_key" \
      -H "Content-Type: application/json" \
      -d '{ "name": "CI/CD replacement" }'
    ```
  </Step>
  <Step title="Update your systems">
    Swap the old key in CI/CD, internal services, and anything that calls Hyze Cloud.
  </Step>
  <Step title="Revoke the old key">
    ```bash
    curl -X DELETE https://api.hyzecloud.com/api/api-keys/key_abc123 \
      -H "Authorization: Bearer hyze_your_key"
    ```
  </Step>
</Steps>

<Callout type="warning">
  A new key's value is shown only once. Store it in your secrets manager immediately.
</Callout>
