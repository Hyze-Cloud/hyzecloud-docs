Use a API de Apps quando quiser deploys a partir de CI/CD, ferramentas internas ou seu próprio painel. Dois caminhos: enviar um ZIP pronto ou apontar para um repositório GitHub conectado.

## Escolha a fonte de deploy

| Fonte | Melhor para |
| --- | --- |
| [ZIP](#deploy-a-partir-de-um-zip) | Artefatos de build gerados por CI |
| [GitHub](#deploy-pelo-github) | Código-fonte em repositório conectado, com auto deploy |

## Deploy a partir de um ZIP

<Steps>
  <Step title="Empacote seu app">
    Crie um ZIP com os arquivos que a Hyze deve executar: entrypoint do app e manifesto de dependências.
  </Step>
  <Step title="Envie a requisição de deploy">
    ```bash
    curl -X POST https://api.hyzecloud.com/api/apps/deploy \
      -H "Authorization: Bearer hyze_sua_chave" \
      -F "file=@app.zip" \
      -F "name=my-api" \
      -F "runtime=node" \
      -F "memoryMB=512" \
      -F "exposePort=3000"
    ```

    `startupCommand` é opcional. Omita (ou use `auto`) para a Hyze detectar o comando certo. Override só se precisar: `-F "startupCommand=node server.js"`.
  </Step>
  <Step title="Verifique o resultado">
    Consulte `GET /api/apps/:appId` até `status: running` e abra os logs:

    ```bash
    curl "https://api.hyzecloud.com/api/apps/app_001/logs?tail=200&timestamps=true" \
      -H "Authorization: Bearer hyze_sua_chave"
    ```
  </Step>
</Steps>

## Deploy pelo GitHub

Use [`POST /api/apps/deploy-from-repo`](/api-reference/apps#deploy-from-github-repo) após conectar o GitHub no dashboard:

```json
{
  "name": "my-api",
  "runtime": "node",
  "memoryMB": 512,
  "exposePort": 3000,
  "autoDeploy": true,
  "repository": {
    "id": "repo_001",
    "owner": "hyzecloud",
    "name": "my-api",
    "branch": "main"
  }
}
```

<Tip>
  Com `autoDeploy: true`, pushes na branch disparam novos deploys automaticamente.
</Tip>

## Runtimes

| Runtime | Auto detect | Observações |
| --- | --- | --- |
| `node` | Sim (API, site estático, Vite, Next…) | Exponha a mesma porta em que seu servidor escuta. |
| `bun` | Sim | Mantenha o lockfile no artefato quando possível. |
| `python` | Sim | Inclua o arquivo de dependências no ZIP. |

Exemplos de override opcional: `node server.js`, `bun run start`, `python main.py`.

<Callout type="info">
  Com porta exposta, informe o **host completo** como subdomínio (ex.: `my-api.hyzecloud.app`), não só o prefixo.
</Callout>

## Problemas comuns

<AccordionGroup>
  <Accordion title="Deploy conclui mas o app não responde">
    Confira `exposePort` e se o servidor escuta em `0.0.0.0`. Veja os logs para descartar crash no boot.
  </Accordion>
  <Accordion title="Comando de start errado">
    Passe `startupCommand` com override (ex.: `node server.js`) ou deixe `auto` para a detecção padrão.
  </Accordion>
</AccordionGroup>
