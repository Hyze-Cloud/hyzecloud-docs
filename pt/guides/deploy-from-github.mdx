title: Deploy pelo GitHub

description: Faça deploy de um app a partir de um repositório GitHub conectado e ative auto deploys.
---

Use deploys por GitHub quando seu código-fonte já estiver em um repositório. A Hyze baixa a branch, instala dependências, detecta o comando de start e inicia o app.

## Pré-requisitos

Conecte o GitHub no dashboard antes de usar este fluxo: **Dashboard → GitHub** (ou verifique o status com `GET /api/integrations/github/status`).

## Deploy de um repositório

```bash
curl -X POST https://api.hyzecloud.com/api/apps/deploy-from-repo \
  -H "Authorization: Bearer hyze_sua_chave" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "api",
    "runtime": "node",
    "memoryMB": 512,
    "exposePort": 3000,
    "autoDeploy": true,
    "repository": {
      "owner": "hyzecloud",
      "name": "api",
      "branch": "main"
    }
  }'
```

<Tip>
  Com `autoDeploy: true`, todo push na branch selecionada dispara um novo deploy automaticamente.
</Tip>

## Verificar o resultado

1. Confirme o status: `GET /api/apps/:appId` — aguarde `status: running`
2. Abra os logs: `GET /api/apps/:appId/logs` para ver a inicialização

## Problemas comuns

<AccordionGroup>
  <Accordion title="404 ao listar repositórios">
    A integração GitHub não está conectada no workspace, ou o app foi instalado com acesso restrito a outros repositórios. Reconecte em **Dashboard → GitHub**.
  </Accordion>
  <Accordion title="Deploy falha na etapa de build">
    Verifique o histórico: `GET /api/apps/:appId/builds`. Causas comuns: lockfile ausente, versão de runtime incompatível ou comando de start errado. O `startupCommand` é opcional — omita e a Hyze detecta (Vite, Next, Node, estático, Python).
  </Accordion>
  <Accordion title="App sobe mas não responde">
    Confira `exposePort`: ele deve ser a mesma porta em que seu servidor escuta, e o servidor deve aceitar conexões em `0.0.0.0`.
  </Accordion>
</AccordionGroup>
